# Генератор ТКП — Приложение 3 «Спецификация оборудования»

## Файлы проекта

Для работы генератора используются:

- `Gen_TKP.xlsm` — книга Excel с макросами;
- `ТКП_шаблон.dotx` — единственный Word-шаблон с нужными закладками; свойство документа «Название» в нём — `ТКП`, поэтому документ, созданный из шаблона, называется «ТКП» (видимый заголовок на первой странице — «Технико-коммерческое предложение»);
- `Module1.bas` — редактируемый исходный код VBA;
- `generate_tkp.py` — автономный генератор на Python;
- `tools/sync_assets.py` — синхронизация исходников VBA, книги Excel и шаблона;
- `tests/test_tkp.py` — автоматические проверки.

`README.md`, `LICENSE` и `requirements-dev.txt` — документация, лицензия и зависимости для разработки и тестов. Исходный `.docx`, копии шаблона `.docx` и заранее сгенерированный результат в репозитории не хранятся. Python-генератор создает результат при запуске.

## Как пользоваться в Excel/Word (Windows)

1. Положите `Gen_TKP.xlsm` и `ТКП_шаблон.dotx` в одну папку. Откройте книгу в **Microsoft Excel для Windows** и разрешите макросы.
2. Заполните номер ТКП, заказчика, объект и предмет на листе `Наценки-Скидки` в ячейках **C2–C5** (они подставляются в закладки `Num`, `HeaderNum`, `Customer`, `Object`, `Subject`). Заполните позиции и количества на листах `SW(w.o.VAT)` (ПО), `1`–`17` (шкафы 1–17) и `Spare parts` (ЗИП).
3. Для проверки списка нажмите **Alt+F8 → ОбновитьСпецификациюТКП**: предпросмотр появится на листе `Спец_ТКП`. Либо нажмите **Alt+F8 → СформироватьТКП**: список обновится автоматически, а в Word откроется новое ТКП с заполненными реквизитами и таблицей Приложения 3 на месте закладки `Spec_Table`.

## Структура таблицы в Приложении 3

Для каждой позиции берутся столбцы **C** (наименование и техническая характеристика), **D** (позиция / артикул), **F** (ед. изм.) и **G** (количество). В спецификацию попадают только строки с количеством **G > 0**. Если формула в столбце **C** содержит `#REF!` и возвращает пустую строку или `"0"`, при `G > 0` и заполненном артикуле в **D** в наименование подставляется значение из **D**. Цены, себестоимость, наценки, строки «Итого...» и работы в Приложение 3 не переносятся.

Разделы включаются в таблицу только при наличии в них хотя бы одной позиции с `G > 0`:

- Заголовок каждого раздела выделяется **жирным шрифтом**, имеет сквозную нумерацию (`1.`, `2.`, `3.` ...); в столбце 4 (`Ед. изм.`) указывается `Компл.`, в столбце 5 (`Кол-во`) — `1`.
- Внутри каждого раздела позиции нумеруются заново (`1.`, `2.`, `3.` ...) обычным шрифтом.
- Порядок разделов:
  1. **Программное обеспечение** — все позиции с `G > 0` с листа `SW(w.o.VAT)`.
  2. **По каждому задействованному шкафу (листы `1`–`17`):**
     - Блок 1 («Спецификация оборудования НВТ») → `Оборудование ПТК (шкаф N)`.
     - Блок 2 («Спецификация оборудования Эксара») → `Телекоммуникационное оборудование для АСУ ТП (шкаф N)`.
     - Блок 3 («Спецификация оборудования 3-х поставщиков») → `Шкафное оборудование ПТК (шкаф N)`.
  3. **ЗИП** — все позиции с `G > 0` с листа `Spare parts`.

## Устройство шаблона

`ТКП_шаблон.dotx` — титульный лист, параметры предложения с условиями, восемь
приложений и справочные страницы. Правила, которые поддерживает
`tools/sync_assets.py` и проверяют тесты:

- **Кегль текста — 12 pt** во всём документе: прямое форматирование, стили и
  нумерация, которые использует документ. Прежние 10 pt и 11 pt больше не
  применяются; колонтитулы сохраняют свой мелкий кегль. Таблица Приложения 3,
  которую строят генераторы, набирается тем же 12 pt.
- **Колонтитул** читается как «Технико-коммерческое предложение № …» и берёт
  номер из строки «Номер» на первой странице: в шаблоне там поле `REF Num`, а
  генераторы подставляют значение из ячейки `C2` листа `Наценки-Скидки`
  (знак «№» добавляется сам, поэтому «№ №» появиться не может).
- **Страница с параметрами предложения** открывается тремя разделами:
  «Исходные данные и допущения» (документ-основание с номером, датой и
  ревизией, перечень сигналов и структура ПТК как исходные данные, условия
  пересчёта — изменение количества сигналов более чем на 10% или сдвиг даты
  начала работ более чем на 3 месяца), «Не входит в объём предложения»
  (датчики и исполнительные механизмы, внешние кабели, строительная часть, АРМ
  и серверы, ИБП, проектная документация стадий «П» и «Р», метрологическая
  аттестация, экспертиза промышленной безопасности, ЗИП, мероприятия по КИИ и
  требованиям ФСТЭК России, согласования в надзорных органах) и «Обязательства
  Заказчика» (готовность площадки, согласование РКД за 10 рабочих дней, доступ
  персонала, технологическая среда для ПНР, ответственный за верхний уровень).
- **Общий срок** в таблице параметров: строка «Общий срок реализации проекта —
  35 недель» стоит после этапов и перед строками «ИТОГО».
- **Условия оплаты**: второй платёж за оборудование и переход права
  собственности привязаны к подписанию УПД, аванс по этапу работ платится за
  7 календарных дней, счёт по обучению выставляется после подписания акта.
  **Условия поставки** говорят только о поставке оборудования на склад
  Заказчика.
- **Приложения 9 и 10** — описание ПТК АРКС400 и страница о компании. У обоих
  стоит метка «Приложение N» с тем же полем `SEQ App`, что и у остальных
  приложений, и обе строки есть в списке приложений, поэтому номера
  пересчитываются сами. Страница «Термины и сокращения» приложением не является
  и номера не получает.
- **Приложение 4** («Перечень передаваемой документации») открывается блоком
  «РКД и ЭД по ГОСТ 34»: структурная схема, схемы соединений внешних проводок,
  принципиальные схемы и схемы подключений, чертежи общего вида шкафов,
  ведомость покупных изделий, ПМИ, протоколы ЗПИ и ПСИ, описание ППО,
  руководства оператора и администратора, инструкция по ТО, формуляр (паспорт),
  ведомость ЗИП. Дальше идут протоколы электроизмерений, исполнительная
  документация, паспорта и сертификаты на покупное оборудование и акт
  выполненных ПНР; общие строки, дублировавшие конкретные документы, убраны.
- **Приложение 5** («Монтажные работы») перечисляет состав работ (разгрузка и
  перемещение к месту установки, монтаж шкафов, межшкафные связи, ЛВС и АРМ,
  сборка кроссов, маркировка кабелей), требования к готовности площадки
  (помещение, температура и влажность, основания и фальшпол, контур заземления,
  питание 1ф/3ф, освещение, пропускной режим, бытовки, места складирования) и
  примечание о том, что в объём работ не входит.
- **Приложение 8** («Календарный план») после таблицы этапов показывает
  диаграмму Ганта: 35 колонок по числу недель, полосы этапов и итоговая строка
  «Общий срок реализации проекта — 35 недель». Шкала недель набрана мельче
  основного текста (8 pt), иначе номера недель не помещаются в колонку;
  названия этапов остаются 12 pt.
- **Сертификация** начинается связкой «ПТК АРКС400 входит в состав системы
  «МИРТС»», дальше идут номера Госреестра, сертификатов и реестров.
- **Последняя страница** — «Термины и сокращения»: ПТК, ППО, РКД, УСО, ЗПИ,
  ПСИ, АРМ, КИИ и остальные сокращения документа.

Разделы страницы с параметрами, блок «РКД и ЭД по ГОСТ 34», список приложений
вместе с метками «Приложение N», примечание к монтажным работам и колонтитул
синхронизация всегда приводит к тексту констант из `tools/sync_assets.py`.
Остальные блоки (строка общего срока, диаграмма Ганта, страница терминов)
добавляются один раз и не перезаписываются, чтобы правки документа вручную не
терялись: чтобы переписать их формулировки, начните с чистой копии шаблона и
запустите инструмент снова. Запуск инструмента на шаблоне прошлой ревизии
сходится к тому же файлу, что и сборка из чистой копии.

## Автономная сборка на Python (без Excel/Word COM)

Установите зависимости и запустите генератор:

```bash
python -m pip install -r requirements-dev.txt
python generate_tkp.py
```

По умолчанию скрипт берет `Gen_TKP.xlsm` и `ТКП_шаблон.dotx` из папки проекта и создает `Технико-коммерческое предложение.docx`. Если в книге нет позиций с количеством `G > 0`, тестовые данные подставляются только в памяти, чтобы команда создала демонстрационный документ; исходная Excel-книга не изменяется.

При необходимости можно указать файлы явно:

```bash
python generate_tkp.py --excel путь/книга.xlsm --template путь/шаблон.dotx --output путь/результат.docx
```

## Синхронизация, тесты и проверки

После изменения VBA, шаблона или структуры предпросмотра выполните:

```bash
python tools/sync_assets.py
python -m ruff check .
python -m unittest discover -s tests -v
```

Правила линтера зафиксированы в `ruff.toml`. Тесты сверяют две реализации одного
алгоритма — VBA-макрос выполняется в памяти через `pyopenvba`, генератор на Python
считает те же данные, и результаты сравниваются построчно. Это удерживает обе
реализации от расхождения.

GitHub Actions также запускает линтер и этот набор тестов при push и создании pull request.

Скрипт синхронизации обновляет `ТКП_шаблон.dotx`, лист предпросмотра в `Gen_TKP.xlsm` и встроенный VBA-модуль. Он не создает копии `.docx` и демонстрационные результаты. Выходной файл `Технико-коммерческое предложение.docx` исключен из Git и может быть создан повторно командой `python generate_tkp.py`.
